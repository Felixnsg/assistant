1. PIPELINE HAZARDS - RECOGNITION & SOLUTIONS
Three Types of Hazards
Hazard Type Definition Common Causes Keywords to Watch
Structure Hazard Resource conflict - hardware can't support all possible combinations Single memory port, limited ALUs "resource busy", "conflict", "single memory"
Data Hazard Instruction depends on result of previous instruction still in pipeline RAW dependencies, load-use scenarios "depends on", "uses result", "previous instruction"
Control Hazard Branch/jump makes next instruction uncertain Conditional branches, function calls "branch", "jump", "if-then", "control flow"
Data Hazard Recognition & Solutions
Identifying Data Hazards
  1. Look for register dependencies between consecutive instructions
  2. Check if destination register of instruction i is source for i+1, i+2, etc.
  3. Consider pipeline depth when evaluating dependency distance
Solution Techniques
  • Forwarding/Bypassing: Route data directly from EX/MEM stages
  • Stalling: Insert NOPs/bubbles when forwarding impossible
  • Code Reordering: Compiler moves independent instructions
Load-Use Hazard Special Case: Cannot forward backward in time! LDUR followed immediately by dependent instruction requires at least 1 stall cycle even with forwarding.
Control Hazard Handling Strategies
Strategy How It Works Performance Impact When to Use
Stall Wait until branch outcome known High penalty (multiple cycles) Simple implementation
Predict Not Taken Continue fetching sequentially No penalty if correct Fall-through common
Predict Taken Fetch from branch target Requires early target calculation Loops (backward branches)
Dynamic Prediction Hardware tracks branch history Best average performance Complex processors
2. DATAPATH DESIGN PATTERNS & COMPONENTS
Key Datapath Elements & Their Roles
Combinational Elements
  • ALU: Arithmetic/logic operations
  • Adders: PC+4, branch target
  • Mux: Select between data sources
  • Sign-extend: Immediate values
Storage Elements
  • PC: Program counter
  • Register File: 32 registers
  • Instruction Memory: Read-only
  • Data Memory: Read/write
Control Signals
  • RegWrite: Enable register write
  • MemRead/Write: Memory ops
  • ALUSrc: ALU input source
  • PCSrc: Next PC source
Instruction Type Recognition for Datapath Design
Instruction Type Key Operations Critical Path Elements Design Considerations
R-Type Read 2 regs → ALU → Write reg Reg file → ALU → Reg file Need 3 register ports (2R, 1W)
Load (LDUR) Read reg → Add offset → Memory → Write reg Reg → ALU → Mem → Reg (longest) Sign-extend needed, memory wait
Store (STUR) Read 2 regs → Add offset → Write memory Reg → ALU → Memory No writeback stage needed
Branch (CBZ) Compare reg → Calculate target → Update PC Reg → ALU & Target calc Early branch resolution helps
Design Pattern Recognition: When asked to "design a datapath for instruction X":
  1. Identify what the instruction does (computation, memory access, control flow)
  2. List required datapath elements (ALU? Memory? How many register reads?)
  3. Trace the data flow from fetch to writeback
  4. Add multiplexers where paths merge
  5. Identify control signals needed
3. CONTROL LOGIC DESIGN & ALU CONTROL
Control Signal Generation Pattern
Two-Level Control Design:
1. Main Control: Opcode → Control signals
2. ALU Control: ALUOp + Function bits → ALU control lines
ALU Control Logic
Instruction Type ALUOp Function Field ALU Control ALU Operation
Load/Store 00 XXXXXX (don't care) 0010 Add (for address)
Branch (CBZ) 01 XXXXXX 0111 Pass input b
R-type 10 Varies by instruction Depends on function Add/Sub/AND/OR
Control Signal Truth Table Pattern
Approach for Control Design Questions
  1. List all instruction types the control must handle
  2. For each instruction, determine:
    • Which registers to read/write (Reg2Loc, RegWrite)
    • ALU operation needed (ALUOp)
    • Memory access requirements (MemRead, MemWrite)
    • Result source (MemtoReg)
    • Next PC calculation (Branch, Uncondbranch)
  3. Create truth table with opcode as input, control signals as output
  4. Minimize if asked (but usually straightforward implementation OK)
4. PIPELINE PERFORMANCE ANALYSIS
Pipeline Performance Metrics
Speedup = Time_nonpipelined / Time_pipelined
Ideal Speedup = Number of pipeline stages (if perfectly balanced)
Pipeline Throughput = 1 instruction / cycle time (steady state)
Pipeline Latency = Number of stages × cycle time
Factors Affecting Pipeline Performance
Performance Enhancers:
  • Balanced pipeline stages
  • Effective forwarding/bypassing
  • Accurate branch prediction
  • Instruction/data cache hits
  • Independent instruction streams
Performance Degraders:
  • Pipeline hazards requiring stalls
  • Unbalanced stage delays
  • Branch mispredictions
  • Cache misses
  • Complex addressing modes
CPI in Pipelined Processors
CPI_pipelined = CPI_ideal + Stalls_per_instruction
CPI_ideal = 1 (for scalar pipeline)
Stalls = Structure_stalls + Data_stalls + Control_stalls
5. PROBLEM SOLVING APPROACHES & PATTERNS
Common Question Types & Approaches
Pattern 1: "Identify hazards in this code sequence"
Approach:
  1. Create a pipeline diagram showing instruction flow
  2. Mark where each instruction reads/writes registers
  3. Look for:
    • RAW dependencies within hazard distance
    • Branches that affect instruction fetch
    • Memory operations that might conflict
  4. Classify each hazard by type
Pattern 2: "Design control logic for new instruction"
Approach:
  1. Understand what the instruction does functionally
  2. Identify which existing datapath elements it uses
  3. Determine if new datapath elements are needed
  4. List all control signals and their required values
  5. Add to control truth table
Pattern 3: "Calculate pipeline performance with hazards"
Approach:
  1. Count total instructions
  2. Identify all hazards and required stall cycles
  3. Calculate total cycles = instructions + total stalls
  4. CPI = total cycles / instruction count
  5. Compare to ideal CPI of 1.0
Pattern 4: "Optimize code to reduce hazards"
Approach:
  1. Identify all data dependencies
  2. Find independent instructions that can be moved
  3. Reorder to increase distance between dependent instructions
  4. Verify semantic correctness after reordering
  5. Count stall reduction
Quick Reference: Hazard Solutions
Hazard Situation Hardware Solution Software Solution Trade-offs
ALU result needed by next instruction Forwarding from EX/MEM Insert independent instruction Hardware complexity vs. code size
Load-use dependency Forwarding + 1 stall Schedule load earlier Unavoidable 1-cycle penalty
Branch decision Branch prediction Loop unrolling Prediction accuracy vs. complexity
Memory port conflict Separate I/D caches — Area/power vs. performance
Pipeline Design Principles
  • All instructions same length: Simplifies fetch and decode
  • Few instruction formats: Simplifies decode and control
  • Memory operands only in loads/stores: Simplifies pipeline stages
  • Operands must be aligned: Allows single-cycle memory access
  • Balance pipeline stages: Minimizes cycle time
Common Mistakes to Avoid:
  • Forgetting that branches have delay slots in some architectures
  • Not accounting for pipeline register delays
  • Assuming forwarding solves all data hazards (load-use still needs stall)
  • Mixing up structural vs. data hazards
  • Forgetting writeback stage when counting pipeline depth
FINAL EXAM STRATEGY: Pipeline questions often combine concepts:
  1. Start by identifying the instruction types involved
  2. Draw pipeline stage diagram if helpful
  3. Mark all dependencies and potential hazards
  4. Apply solutions systematically (forwarding first, then stalls)
  5. Calculate performance impact if asked
  6. Always verify your solution makes logical sense
6. BINARY ARITHMETIC & NUMBER CONVERSIONS
Binary ↔ Decimal Conversion Techniques
Decimal to Binary
  1. Successive Division Method:
    • Divide by 2 repeatedly
    • Record remainders (0 or 1)
    • Read remainders bottom to top
  2. Example: 105₁₀ to binary
    • 105 ÷ 2 = 52 R1
    • 52 ÷ 2 = 26 R0
    • 26 ÷ 2 = 13 R0
    • 13 ÷ 2 = 6 R1
    • 6 ÷ 2 = 3 R0
    • 3 ÷ 2 = 1 R1
    • 1 ÷ 2 = 0 R1
    • Result: 1101001₂
Binary to Decimal
  1. Positional Value Method:
    • Each position = 2^n
    • Multiply bit × position value
    • Sum all products
  2. Example: 1101001₂ to decimal
    • 1×2⁶ = 64
    • 1×2⁵ = 32
    • 0×2⁴ = 0
    • 1×2³ = 8
    • 0×2² = 0
    • 0×2¹ = 0
    • 1×2⁰ = 1
    • Sum: 64+32+8+1 = 105₁₀
Signed Integer Arithmetic (8-bit examples)
Range for n-bit signed: -2^(n-1) to 2^(n-1) - 1
8-bit signed range: -128 to +127
Two's complement: Invert all bits, then add 1
Pattern: Signed Addition/Subtraction Problems
Common Question: "Calculate A - B where A and B are signed 8-bit integers"

Approach:
  1. Convert to binary: Use successive division
  2. For subtraction: Convert to A + (-B)
    • Find two's complement of B
    • Add A + two's complement of B
  3. Check overflow:
    • Addition: Pos + Pos = Neg → Overflow
    • Addition: Neg + Neg = Pos → Overflow
    • Subtraction: Pos - Neg = Neg → Overflow
    • Subtraction: Neg - Pos = Pos → Overflow
  4. Verify result: Convert back to decimal

Floating Point Arithmetic
IEEE 754 Single Precision: 1 sign | 8 exponent | 23 mantissa
IEEE 754 Double Precision: 1 sign | 11 exponent | 52 mantissa
Value = (-1)^S × 1.M × 2^(E-bias)
Bias: Single = 127, Double = 1023
Pattern: Floating Point Representation
Common Question: "Represent X in IEEE 754 format"

Approach:
  1. Convert to binary:
    • Integer part: successive division
    • Fractional part: multiply by 2, take integer
  2. Normalize: 1.xxxxx × 2^n format
  3. Determine fields:
    • Sign bit: 0 for positive, 1 for negative
    • Exponent: n + bias (convert to binary)
    • Mantissa: fractional part after 1.
  4. Pad with zeros to fill mantissa field
Example:
Floating Point Addition/Multiplication
FP Addition Steps
  1. Align exponents: Shift smaller number
  2. Add mantissas: Include hidden 1
  3. Normalize result: Adjust if needed
  4. Round: To fit precision
  5. Check special cases: Overflow/underflow
FP Multiplication Steps
  1. Add exponents: E1 + E2 - bias
  2. Multiply mantissas: (1.M1) × (1.M2)
  3. Normalize: Shift if ≥ 2.0
  4. XOR signs: For result sign
  5. Round and check: Range limits
Quick Verification Techniques
Operation Type Verification Method Common Errors to Check
Binary Addition Convert result to decimal, compare with decimal addition Forgot carry bits, overflow not detected
Two's Complement Complement result should give original when negated Forgot to add 1, wrong bit width
IEEE 754 Conversion Reconstruct decimal from binary representation Wrong bias, unnormalized mantissa
FP Arithmetic Rough decimal calculation should match Exponent alignment errors, rounding
Critical Checks for Arithmetic Problems:
  • Overflow Check: Result outside representable range?
  • Sign Check: Does sign make sense for operation?
  • Magnitude Check: Is |result| reasonable?
  • Binary Length: Correct number of bits?
  • Decimal Verification: Convert back and verify
Exam Strategy for Arithmetic Problems:
  1. Read carefully: Note bit width and signed/unsigned
  2. Show all work: Conversions, carries, borrows
  3. Check overflow/underflow: Especially for signed ops
  4. Verify with decimal: Quick sanity check
  5. For IEEE 754: Remember bias and hidden bit
  6. Time management: FP problems take longer
7. BINARY DIVISION ALGORITHMS
Restoring Division (Slow & Simple)

Analogous to grade-school long division. It performs a subtraction and, if the result is negative, restores the original value.

Approach:
  1. Initialize: Remainder (R) = Dividend.
  2. Shift: Shift Remainder left by 1 bit.
  3. Subtract: R = R - Divisor.
  4. Check & Set Quotient Bit:
    • If R ≥ 0 (MSB=0), set quotient bit to 1.
    • If R < 0 (MSB=1), set quotient bit to 0 and restore the remainder (R = R + Divisor).
  5. Repeat: Repeat shift/subtract/check for n steps (where n is the number of bits).
Non-Restoring Division (Faster)

Improves on restoring division by eliminating the restoration step. Instead, it either adds or subtracts based on the current remainder's sign.

Approach:
  1. Initialize: Remainder (R) = Dividend.
  2. Check Remainder Sign:
    • If R ≥ 0 (MSB=0), shift left, then subtract Divisor.
    • If R < 0 (MSB=1), shift left, then add Divisor.
  3. Set Quotient Bit:
    • If R ≥ 0 (MSB=0) after the operation, set quotient bit to 1.
    • If R < 0 (MSB=1), set quotient bit to 0.
  4. Repeat: Repeat check/op/set for n steps.
  5. Final Correction: If the final remainder is negative, add the divisor back to get the correct final remainder.
Example: 7 ÷ 3 (0111 ÷ 0011) using 4-bit unsigned division
Restoring Method:
  1. R = 0000, Q = 0111. Shift R,Q left: R=00001, Q=1110. Subtract 3 (0011): 00001 - 0011 -> R is negative. Set Q₀=0, Restore R.
  2. Shift R,Q left. Subtract 3. Result positive. Set Q₁=1.
  3. ...and so on.
Result: Quotient = 2 (0010), Remainder = 1 (0001). Non-restoring follows a similar but more direct path.
Algorithm Comparison
Aspect Restoring Division Non-Restoring Division
Speed Slower due to potential restore step (add/sub). Faster, as each cycle is a predictable shift and add/sub.
Complexity Simpler logic, easier to understand and implement. More complex control logic to decide between adding and subtracting.
Hardware Requires ALU for both addition and subtraction. Requires ALU for both addition and subtraction.
Use Case Good for educational purposes or simple CPUs. Common in processors where performance is critical.
8. MEMORY HIERARCHY & CACHE FUNDAMENTALS
Core Concept: The Speed vs. Size Trade-off

The fundamental challenge is that fast memory (SRAM) is expensive and small, while large memory (Disk) is cheap and slow. The memory hierarchy creates the illusion of a memory that is both large and fast by organizing storage in levels.

The Principle of Locality
Temporal Locality

If an item is accessed, it's likely to be accessed again soon.

Example: Instructions in a loop or variables used repeatedly.
Spatial Locality

If an item is accessed, items with nearby addresses are likely to be accessed soon.

Example: Sequential instruction fetching or accessing array elements in order.
Hierarchy Terminology
Term Definition
Block / Line The unit of data copied between levels of the hierarchy.
Hit The requested data is found in an upper, faster level (e.g., the cache).
Miss The requested data is not found in the upper level, requiring a fetch from a lower, slower level.
Miss Penalty The time required to fetch a block from a lower level and deliver it to the upper level.
Memory Technology Types
Technology Access Time Cost / GB Primary Use Case
SRAM (Static RAM) ~0.5 - 2.5 ns Very High ($2k - $5k) L1/L2 Cache Memory
DRAM (Dynamic RAM) ~50 - 70 ns Moderate ($20 - $75) Main Memory
Flash Storage Much faster than disk Low (between DRAM/Disk) SSDs, USB Drives
Magnetic Disk ~5 - 20 ms Very Low (<$2) Permanent Storage (HDD)
Key Technology Characteristics:
  • DRAM: Stores data as charge in a capacitor; must be periodically refreshed. Performance is improved with features like row buffers and banking.
  • Flash: Non-volatile memory that wears out after many write cycles. Requires wear leveling to distribute writes and extend lifespan.
  • Disk: Performance limited by physical movement: seek time (moving the arm) and rotational delay (waiting for the sector).
Cache Fundamentals: Direct Mapped Cache
A simple and common cache organization where each block from main memory maps to exactly one location in the cache.
(Block Address) MOD (Number of Blocks in Cache)
How it works: The low-order bits of the block address are used as an index to determine which cache line to check. This makes finding a block fast, but can lead to conflicts if multiple memory blocks map to the same cache line.
