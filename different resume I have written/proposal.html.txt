    <h2>1. Project Title</h2>
    <p>A Real-Time, Multi-Stage Scene Analysis System with Conversational Querying: A Data Structures Approach</p>
    
    <h2>2. Introduction / Problem Statement</h2>
    <p>This project is about building a smart monitoring system that watches your environment in real-time. We'll use a Raspberry Pi with a camera to capture video, then send it to a server that uses AI (YOLOv8) to detect objects. The cool part? You can ask the system questions about what it's seeing, and it'll give you a summary using an AI chatbot. Think of it as having a smart security guard that can tell you what's happening around you.</p>
    
    <h2>3. Objectives</h2>
    <ul>
        <li><strong>Get the video:</strong> Set up the Raspberry Pi camera to capture video frames continuously and add timestamps to each frame.</li>
        <li><strong>Send the data:</strong> Stream video frames from the Pi to our server using WebSockets (think of it as a live video feed).</li>
        <li><strong>Analyze what's there:</strong> Use YOLOv8 AI on the server to detect objects in each frame. Get data like what objects we found, where they are, and how confident the AI is about each detection.</li>
        <li><strong>(Bonus if we have time):</strong> Add action recognition to see what people are doing, not just that they're there.</li>
        <li><strong>Store and organize:</strong> Use smart data structures (queues, lists, etc.) to handle all this data efficiently and create summaries like "how many people are here" or "what was seen in the last 5 minutes."</li>
        <li><strong>Make it interactive:</strong> Let users ask questions and get natural language answers about what the system is seeing, using an AI chatbot interface.</li>
        <li><strong>Make it fast:</strong> Run everything at the same time - capture video, process it, and respond to users - without slowing down.</li>
    </ul>
    
    <h2>4. System Design</h2>
    
    <h3>Hardware Components</h3>
    <ul>
        <li>Raspberry Pi (with camera interface)</li>
        <li>Camera (Raspberry Pi Camera Module or compatible USB webcam)</li>
        <li>Host machine (Laptop/Desktop, for server component)</li>
    </ul>
    
    <h3>Software Components</h3>
    <ul>
        <li><strong>Client (Raspberry Pi):</strong> Python, <code>OpenCV</code> (or <code>picamera2</code>), <code>websockets</code>, <code>threading</code>, <code>queue</code>.</li>
        <li><strong>Server (Host Machine):</strong> Python, <code>websockets</code>, <code>OpenCV</code>, <code>ultralytics</code> (for YOLOv8), <code>asyncio</code>, <code>threading</code> (or <code>multiprocessing</code>), <code>collections</code>, standard JSON library. For LLM interaction, existing modules for chat management and conversation memory (persisted as JSON) will be adapted.</li>
    </ul>
    
    <h4>A. Data Acquisition (Raspberry Pi)</h4>
    <p>We'll have one thread that grabs video frames and timestamps them.<br>
    Data format: <code>(timestamp, frame_bytes)</code>.<br>
    <strong>Data Structure:</strong> We'll use a <code>queue.Queue</code> to store frames while they're being sent over the network.</p>
    
    <h4>B. Data Transmission & Intermediate Storage (Raw)</h4>
    <p>Frames get converted to JPEG and sent via WebSockets (like a live video stream).<br>
    <strong>Server-side:</strong> Incoming frames get stored in an <code>asyncio.Queue</code> before the AI processes them.</p>
    
    <h4>C. Data Processing (Server-side)</h4>
    <ol>
        <li><strong>YOLOv8 Object Detection:</strong> A separate process runs the AI to find objects in each frame.<br>
        Output format: <code>(timestamp, frame_id, list_of_detections)</code> where each detection looks like: <code>{'class': 'person', 'bbox': [x,y,w,h], 'confidence': 0.85}</code>.</li>
        <li><strong>Data Organization and Summary:</strong>
        <ul>
            <li><code>collections.deque(maxlen=N)</code>: Think of this as a sliding window that keeps the last N detections. Old stuff gets automatically removed.</li>
            <li><code>collections.Counter</code>, Lists, and Dictionaries: When someone asks a question, we count things like "how many people" or organize the data for the chatbot.</li>
            <li>Filtering & Sorting: We can pull specific info like "show me what happened in the last minute."</li>
        </ul>
        </li>
    </ol>
    
    <h4>D. Data Presentation & LLM Interaction (Server-side)</h4>
    <p>An async task handles user questions.<br>
    The system looks at the recent detections, processes them, and creates a summary.<br>
    This summary gets sent to the AI chatbot for a natural language response.<br>
    <strong>JSON and Chat History:</strong> We use JSON to talk to the chatbot and save conversation history (like a chat log in <code>past_conversations.json</code>). This lets the system remember previous questions.<br>
    <strong>Why this matters:</strong> Instead of just raw detection data, users get useful answers like "Yes, there are 2 people in the room right now."</p>
    
    <h4>E. Concurrency Model</h4>
    <ul>
        <li><strong>Raspberry Pi:</strong> Thread 1 (Capture video) → <code>queue.Queue</code> → Thread 2 (Send to server).</li>
        <li><strong>Server:</strong>
        <ul>
            <li>Async Task (Receive video) → <code>asyncio.Queue</code></li>
            <li>Async Task/Thread (Run AI detection) → <code>collections.deque</code> (Store results)</li>
            <li>Async Task (Answer user questions) reads from storage and chats with the AI.</li>
            <li>We'll use locks if needed to prevent data conflicts when multiple processes access the same storage.</li>
        </ul>
        </li>
    </ul>

    <h2>6. Practical Use and Relevance of Information</h2>
    <p>This system could be the start of something really useful - think smart security cameras, awareness tools for busy environments, or activity monitoring. Instead of just seeing raw video footage, you get simple summaries like "Currently seeing 2 people and 1 car. Someone was at the entrance 5 seconds ago." It takes all that visual data and turns it into something you can actually use quickly.</p>
    
    <h2>7. Data Structure Focus & Justification</h2>
    <p>This project is all about using the right data structures to make everything run smoothly:</p>
    
    <table class="data-structure-table">
        <tr>
            <th>Data Structure</th>
            <th>Purpose</th>
            <th>Justification</th>
        </tr>
        <tr>
            <td>Queues (queue.Queue, asyncio.Queue)</td>
            <td>Manage data flow between concurrent stages</td>
            <td>Essential for decoupling producers and consumers, managing backpressure</td>
        </tr>
        <tr>
            <td>Deques (collections.deque)</td>
            <td>Store rolling window of time-series data</td>
            <td>O(1) append/pop performance for streaming applications</td>
        </tr>
        <tr>
            <td>Counters (collections.Counter)</td>
            <td>Frequency analysis of detected objects</td>
            <td>Efficient way to perform categorical data analysis</td>
        </tr>
        <tr>
            <td>Lists and Dictionaries</td>
            <td>Organize and structure data internally</td>
            <td>Fundamental for data organization and LLM communication</td>
        </tr>
        <tr>
            <td>JSON</td>
            <td>Data serialization and persistence</td>
            <td>Key for LLM communication and conversation history</td>
        </tr>
    </table>
    
    <p>These data structures work together to make the system fast and responsive while handling real-time video processing and user questions.</p>
    
    <h2>8. Potential Challenges</h2>
    <ul>
        <li>Making sure different parts of the system don't interfere with each other when accessing shared data.</li>
        <li>Dealing with network delays and possible data loss between the Pi and server.</li>
        <li>Getting the AI detection to run fast enough for real-time use.</li>
        <li>Writing good prompts for the chatbot and making sure it gives useful responses.</li>
    </ul>
